## 修复：云账号注册「填完验证码才报 Username 不合规」

**现象**：设置 → 账号 → 云账号 → 注册，点「获取验证码」正常、邮件收到，
但填入验证码点「完成注册」后报
`invalid SignUpRequest.Username: value does not match regex pattern "^$|^[a-z][0-9a-z_-]{5,24}$"`，
且界面提示被 `invalid_argument` 的通用文案带偏成「验证码错误或已过期」。

**根因（两层）**：
1. **调用时机**：CloudBase js-sdk 的 `auth.signUp({email,...})` 只调用发码接口
   （`getVerification`），**不校验也不发送 username**。真正的 `authApi.signUp`
   是 SDK 在 `signUp().verifyOtp({token})` 闭包里补发的
   （`delete n.email; authApi.signUp({...n, email, verification_token, verification_code})`）。
   → 所以字段校验错误只在「提交验证码」那一步抛回，与验证码本身无关。
2. **正则不对齐**：渲染层 `USERNAME_PATTERN` 写的是
   `/^[A-Za-z0-9][A-Za-z0-9\-_.:+@]{4,23}$/`（允许大写、`.` `:` `+` `@`、5 位），
   服务端要求 `^$|^[a-z][0-9a-z_-]{5,24}$`（**留空放行**；6-25 位；首字符必须小写字母；
   仅 `a-z 0-9 _ -`）。客户端比服务端宽松 → 非法值能通过前端检查。

**改动**：
- `src/components/settings/SettingsCloudAccountSection.tsx`
  - `USERNAME_PATTERN` 收紧为 `/^[a-z][0-9a-z_-]{5,24}$/`，抽出 `USERNAME_HINT` 常量
  - 表单里给用户名字段加了一行规则说明（复用 `settings-item__hint`）
- `electron/cloud/cloudbase-client.ts`
  - 新增 `FIELD_RULE_ERRORS`，在 `describeCloudError` 里把 `SignUpRequest.Username` /
    `SignUpRequest.Password` 的正则校验错误翻成中文，并指向「点返回改用户名后重新获取验证码」
  - `describeCloudError` 结构顺手改成早返回（网络分支 → 字段规则分支 → 兜底）

**给用户的即时解法**：用户名改用纯小写字母开头、6 位以上、只含 `a-z 0-9 _ -`（如 `stellara_user`），
或直接留空不填；然后点验证码页的「返回」重填 → 重新「获取验证码」→ 填新码。

**未做**：`vitest.config.ts` 仍未排除 `.worktrees/`（见 MEMORY.md 的测试陷阱）。

**验证**：`npx tsc -p tsconfig.json --noEmit && npx tsc -p electron/tsconfig.json --noEmit` 通过。

## 修复：注册「成功但未取到用户信息」（SDK user 形状错位）

**现象**：验证码校验通过后报 `注册成功但未取到用户信息 / 请尝试直接登录 / unknown`。

**根因**：`cloud-auth-manager.ts` 的 `toAccount()` 假设 user 形如
`{ uid, email, username, name, phoneNumber }`，但 **SDK v3 返回的是 Supabase 形状**
（内部先跑 `convertToUser()`，见 js-sdk auth 包的 `convertToUser`）：

```
{ id, aud, role, email, phone, confirmed_at, created_at, updated_at,
  app_metadata:  { provider, providers },
  user_metadata: { uid, username, name, nickName, picture, avatarUrl, ... },
  identities: [...] }
```

顶层**没有** `uid`/`username`/`name`/`phoneNumber` → `user?.uid` 恒 undefined →
`toAccount` 返回 null → 抛「未取到用户信息」。调用方全部写着 `as never` 强转，
所以 `npm run typecheck` 完全看不见这个错。
**影响面**：4 处调用全中 —— `sendSignUpCode` 的已注册兜底、`verifySignUp`、
`signInWithPassword`、`restoreSession`（即注册/登录/会话恢复都拿不到账号）。

**改动**：
- 新增 `electron/auth/cloud-user.ts`：`RawCloudUser` 类型 + `toCloudAccount()` 归一化
  （`uid = user.uid ?? user.id ?? user.sub ?? user_metadata.uid`；空串 email/phone → undefined）
- 新增 `electron/auth/cloud-user.test.ts`（6 例，含 Supabase 形状回归）
- `electron/auth/cloud-auth-manager.ts`：删掉本地 `toAccount`，新增 `resolveAccount()`
  统一三层兜底（`data.user` → `data.session.user` → `getUser()`），4 处调用点全部改用它，
  并移除所有 `as never` 强转 → 以后形状漂移 typecheck 能报出来

**验证**：两侧 typecheck 通过；`npx vitest run electron/auth electron/store/cloud-links.test.ts` 13 passed。

**顺带发现**：`npm run lint` 是坏的 —— 仓库里没有任何 `eslint.config.*`，
ESLint 10 直接报 "couldn't find an eslint.config"（未修）。

## 云账号登录/注册界面设计（已出设计稿，尚未实现）

**顺带修掉的 CSS bug**：`src/styles/cloud-account.css` 的 `.cloud-field__input`
原本写 `height: var(--space-input-h, 32px)` —— `--space-input-h` 是**内边距** token（10px），
而且它真实存在、fallback 32px 永不生效 → 登录/注册表单里的输入框被压成 **10px 高**，
覆盖了 `.account-input` 的 30px。已改为 `var(--control-height-sm, 30px)`。
（教训：`--space-*` 是间距，高度要用 `--control-height*`。）

**设计要点（6 条）**：
1. 登录/注册切换：弱 tab → **分段控件**（轨道 #f4f5f7 + 激活项 accent-tint 底）
2. 注册拆成**两步 + 步骤条**：① 账号信息 → ② 邮箱验证；第二步顶部回显邮箱并提供「修改」
3. 校验前置：用户名规则 / 密码强度 / 确认密码在**填写时**反馈，不再等提交才报错
   （正对上一轮 `SignUpRequest.Username`「错误来得太晚」的根因）
4. 验证码：**6 格分格输入** + 行内倒计时 + 「重新发送 59s」冷却
5. 错误分层：**字段级 inline 红框**（用户能改）vs **顶部横幅**（系统级、不指向字段）；
   并把内部 error code（如 `unknown`）从横幅撤掉
6. 补入口「忘记密码？」（SDK 有 `resetPasswordForEmail`，需新增 IPC）

**落地成本**：要动 `SettingsCloudAccountSection.tsx`（状态机扩到 4 态）、`cloud-account.css`
（分段控件/步骤条/OTP 样式）、`shared/ipc.ts` + preload + main（忘记密码）+ `src/dev-preview.ts`（预览桩）。
验证码步骤收益最高、成本最低。

**用户选择**：全量实现（分段控件 + 两步注册 + 实时校验 + 6 格验证码 + 错误分层，不含忘记密码）。
