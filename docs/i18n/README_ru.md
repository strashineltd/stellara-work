**Stellara Work** — это **локально-ориентированный** настольный агент, работающий аналогично персональному Codex. Используйте собственный API-ключ, совместимый с OpenAI (`base_url + api_key`), для совместной работы с агентом на рабочем столе — чтение файлов, редактирование кода, выполнение команд — с возможностью просмотра и одобрения на каждом этапе.

API-ключи, сессии, файлы и конфигурации **никогда не покидают ваше устройство**. Stellara Work не загружает данные на внешние серверы.

## Основные возможности

| | Возможность | Описание |
|---|---|---|
| 🔒 | **Локальная конфиденциальность** | API-ключи шифруются через системную связку ключей (macOS) / DPAPI (Windows); все данные хранятся локально |
| 🧠 | **Собственная модель** | Совместимость с любым эндпоинтом протокола OpenAI; встроенные пресеты GLM, DeepSeek, Kimi, MiniMax; поддержка неограниченного количества пользовательских моделей |
| ✅ | **Режим планирования + контроль одобрения** | Каждая запись файла и выполнение команды требуют вашего явного одобрения |
| 💬 | **Потоковый диалог** | Рендеринг Markdown в реальном времени, представление diff и карточки вывода команд |
| 🗂️ | **Рабочее пространство проекта** | Указание любой папки, агент работает с реальным кодом для чтения, записи и проверки |
| 🧰 | **Навыки и MCP** | Расширение возможностей агента с помощью пользовательских навыков и MCP-серверов |
| 🧠 | **Центр памяти** | Постоянная, доступная для поиска память между сессиями |
| 📎 | **Вложения** | Перетаскивание файлов и изображений в любую сессию |
| 📂 | **Файловый менеджер** | Боковая панель с деревом файлов, поддержка создания файлов/папок |
| 🎨 | **Дизайн-система** | Единые переменные стилей UI и дизайн рабочего пространства |

## Быстрый старт

### Требования к среде

- Node.js 20+
- Windows: Python 3.x + Visual Studio Build Tools (разработка настольных приложений C++) — требуется только при первом `npm install`
- macOS / Linux: дополнительная установка не требуется

### 1. Установка зависимостей

```bash
npm install
```

На macOS/Linux можно использовать `bash setup.sh` (проверка Node, установка зависимостей, запуск тестов).

### 2. Запуск

```bash
npm run dev
```

При первом запуске следуйте инструкциям для выбора модели и ввода API-ключа. Ключ шифруется и доступен только основному процессу.

### 3. Основные скрипты

```bash
npm run dev          # Режим разработки (Vite HMR + Electron)
npm test             # Запуск тестов
npm run typecheck    # Проверка типов для обоих процессов
npm run package:mac  # Сборка macOS dmg/zip (только macOS)
npm run package:win  # Сборка Windows NSIS установщика
```

## Модель безопасности

- `nodeIntegration: false` — рендер-процесс не может использовать `require('fs')`
- `contextIsolation: true` — JS рендер-процесса изолирован от preload
- `sandbox: true` — рендер-процесс работает в песочнице
- Внешние URL ограничены протоколами `http/https/mailto`
- Все IPC-обработчики проверяют источник отправителя
- Все опасные операции (запись файлов, выполнение команд) требуют явного одобрения

## Архитектура

```
electron/                  # Основной процесс Electron
├── main.ts                # Точка входа + IPC handlers
├── preload.ts             # contextBridge API
├── agent/                 # Цикл агента, планирование, инструменты (fs / shell / grep / git)
├── llm/                   # Клиент, совместимый с OpenAI + потоковая передача SSE
├── memory/                # Постоянное хранилище памяти
└── config/                # Зашифрованное хранилище ключей (safeStorage)
src/                       # Рендер-процесс React
├── components/            # Чат, карточки планов, настройки, руководство, главная
├── styles/                # Переменные дизайна + CSS рабочего пространства
└── lib/                   # Утилиты рендер-процесса
shared/                    # IPC-контракты, разделяемые между процессами
```

Технологический стек: Electron · React 19 · TypeScript · Vite · better-sqlite3 · CodeMirror 6
