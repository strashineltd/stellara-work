# Stellara Work 克制功能型动效系统

> 日期：2026-08-22
> 状态：已确认，进入分批实施

## 1. 背景

Stellara Work 已有一套基础动效：`120ms / 180ms / 220ms` 时长、两条缓动曲线、侧栏与检查器方向性进入、浮层和消息条目进入、状态旋转与脉冲，以及全局 `prefers-reduced-motion` 处理。

当前主要问题不是缺少动画，而是动画语义不完整：

- 侧栏、检查器、弹窗和菜单进入平滑，但关闭时立即卸载。
- 部分菜单的进入方向与实际出现方向不一致。
- 所有聊天历史条目在任务页重新挂载时都会重播进入动画。
- 少量控件绕过 token，状态变化属性与 transition 覆盖不一致。
- 进度条动画 `width`，会触发布局计算。
- reduced-motion 仅把时长压缩到 `0.01ms`，Presence 生命周期仍缺少明确的直接完成策略。

本设计在不引入动画库的前提下，建立一套克制、可预测、可测试的程序级动效系统。

## 2. 已确认决策

- 动效强度：克制功能型。
- 首要目标：让打开与关闭更连贯。
- 技术方向：原生 CSS + 小型 Presence 生命周期工具。
- 交付目标：设计确认后继续在当前程序中分批落地。
- 不引入 Motion、Framer Motion 或其他动画依赖。
- 保留当前 Calm Workspace / Studio Desk 视觉语言。

## 3. 设计原则

### 3.1 动效语义

动效表达“工作台物件归位”，只用于说明：

- 元素从哪里出现、向哪里离开。
- 哪个状态刚刚发生变化。
- 哪个任务仍在执行。
- 哪个表面属于当前交互层级。

动效不用于装饰、庆祝、制造等待感或吸引用户持续注意。

### 3.2 允许的属性

- `opacity`
- `transform`
- `color`
- `background-color`
- `border-color`
- `box-shadow`

不增加宽度、高度、margin、padding、top、left 或滚动位置动画。

### 3.3 静态优先区域

以下区域不增加内容动画：

- 流式助手正文、Markdown、代码块、终端输出和 diff 行。
- 文件树批量展开与文件预览。
- CodeMirror 编辑器与 MergeView。
- 记忆搜索结果、设置长列表和实时过滤结果。
- 主题切换。
- 检查器拖拽宽度。
- 自动滚动与会话历史加载。

## 4. 动效 Token

保留现有 token：

| Token | 值 | 用途 |
|---|---:|---|
| `--motion-fast` | `120ms` | hover、focus、press、选择状态 |
| `--motion-base` | `180ms` | 浮层、内容条目、轻量页面进入 |
| `--motion-slow` | `220ms` | 侧栏、检查器、弹窗表面 |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 颜色、边框、阴影状态变化 |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 元素进入与归位 |

新增 token：

| Token | 值 | 用途 |
|---|---:|---|
| `--motion-exit` | `140ms` | 表面与浮层退出 |
| `--ease-in` | `cubic-bezier(0.4, 0, 1, 1)` | 退出 |
| `--motion-distance-xs` | `2px` | 状态提示、设置 tab |
| `--motion-distance-sm` | `4px` | 菜单、消息条目、页面内容 |
| `--motion-distance-md` | `8px` | 侧栏、检查器 |
| `--motion-loop-spin` | `800ms` | 活动中旋转状态 |
| `--motion-loop-pulse` | `1200ms` | 思考与录制状态 |

退出比进入短，避免关闭操作感觉迟滞。禁止新增弹簧、回弹、过冲或 scale 弹跳曲线。

## 5. Presence 架构

### 5.1 职责

新增一个无外部依赖的 `usePresence` hook，只负责把逻辑可见性转换为视觉生命周期。

输入：

- `present: boolean`
- `exitMs: number`，默认使用 `--motion-exit` 对应的 `140ms`；样式契约测试负责保持 JS 默认值与 CSS token 一致

输出：

- `mounted: boolean`
- `state: 'entering' | 'open' | 'closing'`
- `completeExit(event?)`

业务组件继续以现有布尔状态为唯一事实来源。Presence 不接管业务状态、不阻止关闭回调，也不改变 IPC 或数据流。

### 5.2 状态流

```text
未挂载
  -> present=true
entering
  -> 下一动画帧
open
  -> present=false
closing
  -> 根节点退出动画完成或超时兜底
未挂载
```

快速重开时：

```text
closing
  -> present=true
entering/open
```

重开必须取消待卸载计时器，旧的 `animationend` 不能卸载已经重新打开的节点。

### 5.3 结束判定

- 优先由根节点 `transitionend` 完成退出。
- 只接受 `event.target === event.currentTarget`，忽略子元素动画事件。
- 使用 `exitMs + 50ms` 的超时作为兜底。
- 组件卸载时清理 requestAnimationFrame、事件与计时器。
- React Strict Mode 重复执行 effect 时不得留下悬挂任务。

### 5.4 关闭阶段

`state='closing'` 时：

- 根节点设置 `data-motion-state="closing"`。
- 立即设置 `pointer-events: none`。
- 从可访问树隐藏，并使内部控件不可聚焦。
- 业务关闭、批准、拒绝、删除或终止语义立即生效。
- Presence 仅保留离场画面，不保留可交互状态。

## 6. 界面动效矩阵

### 6.1 左侧栏与右检查器

| 状态 | 左侧栏 | 右检查器 |
|---|---|---|
| 进入 | `opacity 0 -> 1`，`translateX(-8px -> 0)`，`220ms` | `opacity 0 -> 1`，`translateX(8px -> 0)`，`220ms` |
| 退出 | 反向移动，`140ms` | 反向移动，`140ms` |

- 退出期间保留面板布局槽位。
- 面板卸载后中央内容立即完成最终重排。
- 不动画面板宽度，不让内容宽度追赶鼠标或状态。
- macOS 标题栏开关及红绿灯下方定位保持静止，动画只作用于侧栏面板表面。
- 920px 以下覆盖层继续使用同一方向，但不触发中央内容重排。

### 6.2 弹窗

适用范围：设置、命令面板、项目创建、文件树、记忆编辑/删除、清空任务确认。

| 层 | 进入 | 退出 |
|---|---|---|
| backdrop | `opacity 0 -> 1`，`180ms` | `opacity 1 -> 0`，`140ms` |
| surface | `opacity 0 -> 1`，`translateY(6px -> 0)`，`220ms` | `opacity 1 -> 0`，`translateY(0 -> 4px)`，`140ms` |

- 不使用 scale。
- 关闭开始即恢复焦点并禁用离场表面交互。
- backdrop 与 surface 共用一个 Presence 生命周期，避免一层先消失。

### 6.3 菜单与气泡

- 菜单位于触发器下方：从 `translateY(-4px)` 进入。
- 菜单位于触发器上方：从 `translateY(4px)` 进入。
- Header、模型、会话与上下文菜单进入使用 `180ms`；高频输入联动的斜杠菜单进入使用 `120ms`；所有菜单退出使用 `120ms`。
- 斜杠菜单固定使用向上方向。
- 会话菜单依据运行时翻转结果设置 `data-side='top' | 'bottom'`。
- 关闭开始立即把焦点还给触发器或保留在原输入框。

### 6.4 页面与设置内容

- 首页、项目、文件、记忆只对新页面根内容执行一次 `180ms / 4px` 进入。
- 不做整页退出，不做左右滑屏。
- 任务页历史记录不参与页面进入动画。
- 设置外框始终静止；tab 内容使用 `120ms` 淡入和 `2px` 归位。
- tab 切换不动画 width 或 height。

### 6.5 引导流程

- 欢迎、模型选择、连接详情每个新步骤使用 `180ms / 4px` 进入。
- 异步测试、保存、成功和失败状态仅做颜色、图标与轻 opacity 反馈。
- 不在请求尚未完成时播放“成功离场”。

## 7. 任务流与状态动效

### 7.1 聊天条目

只给本次实时追加的离散条目增加动画标记：

- 用户消息。
- 新助手占位条目。
- 工具调用与工具结果。
- 计划、审批请求、汇总和最终报告。

进入方式为 `opacity 0 -> 1` 和 `translateY(4px -> 0)`，时长 `180ms`。

以下情况不添加动画标记：

- 会话历史加载。
- 会话切换。
- 从其他主页面返回任务页。
- 同一助手条目的流式 token 更新。
- 已存在条目的内容补全或 Markdown 重排。

实现时需要稳定区分“实时追加”和“批量载入”，不能继续让所有 `.entry` 默认播放动画。

### 7.2 审批、错误与警告

- 进入使用 `120ms / 2px`。
- 不使用重复脉冲、抖动或高频颜色闪烁。
- 批准、拒绝、终止和删除立即完成语义状态，不等待退出动画。
- 状态节点必须立即进入 `alert`、`status` 或 `alertdialog` 语义。

### 7.3 连续状态

- 应用加载与计划执行统一使用 `800ms` 旋转。
- 助手思考与快捷键录制统一使用 `1200ms` 低频脉冲。
- 循环只在真实活动状态存在。
- 页面隐藏时暂停非必要循环。
- reduced-motion 下使用静态图标和状态文字。

### 7.4 进度

- 使用 `transform: scaleX()` 替代 `width` transition。
- 设置 `transform-origin: left center`。
- 进度更新使用 `220ms` 与 `--ease-out`。
- 完成态只改变颜色和图标，不播放庆祝或弹跳动画。

### 7.5 微交互

- 按钮、导航与卡片反馈统一使用 `120ms`。
- 位移上限：按钮和快捷动作 `1px`，项目卡片 `2px`。
- 不使用 scale。
- 展开/收起只旋转箭头，内容高度立即变化。
- 修正 transition 属性遗漏；危险按钮的 `filter` hover 改为颜色反馈，避免瞬间跳变与额外合成。

## 8. 无障碍与焦点

### 8.1 Reduced motion

系统偏好减少动态效果时：

- `usePresence` 不等待退出动画，直接完成卸载。
- 非必要动画与 transition 关闭。
- 连续旋转和脉冲关闭。
- 状态文字、图标、颜色和 ARIA 语义保持完整。
- 不依赖 `0.01ms` 动画事件推动业务状态。

### 8.2 焦点规则

- 弹窗打开后按现有语义聚焦名称、搜索、内容或安全默认动作。
- 弹窗关闭开始时立即把焦点还给触发器。
- 菜单关闭后焦点回到触发器；斜杠菜单继续让焦点留在输入框。
- 离场节点必须 `inert`，不能被 Tab、快捷键或指针访问。
- 动效不改变现有键盘命令语义。

### 8.3 语义时序

视觉动画不能延迟：

- `role='alert'`
- `role='status'`
- `role='alertdialog'`
- `aria-expanded`
- `aria-pressed`
- 操作成功、失败、批准或拒绝状态

## 9. 异常与竞态处理

- 快速开关：取消旧退出任务，以最后一次逻辑状态为准。
- 父组件卸载：立即清理 Presence，不等待动画。
- transition 事件缺失：超时兜底完成卸载。
- 子元素 transition 结束：不得误触发父 Presence 完成。
- reduced-motion 在运行中变化：当前退出立即完成，后续进入保持静态。
- 页面进入后台：暂停循环，不影响一次性离场清理。
- 业务请求失败：保留输入与错误语义，动画不得清空或覆盖错误状态。

## 10. 性能约束

- 不使用 `transition: all`。
- 不长期设置 `will-change`。
- 大型表面只在进入/退出期间使用 transform 与 opacity。
- 不给历史消息、文件树节点或搜索结果批量 stagger。
- 不为流式 token、自动滚动或拖拽宽度添加 transition。
- 清理重复 spinner keyframe 与无运行时引用的动画选择器。
- 所有无限循环必须由真实活动状态控制。

## 11. 测试策略

### 11.1 Presence 单元测试

- false -> true：立即挂载并进入 `entering/open`。
- true -> false：保持挂载并进入 `closing`。
- 根节点退出 transition 结束：完成卸载。
- 子元素 transition 结束：不完成卸载。
- 没有 transition 事件：超时完成卸载。
- closing 期间重开：取消卸载并保持挂载。
- Strict Mode：无重复计时器和卸载后更新。
- reduced-motion：关闭时直接卸载。

### 11.2 组件测试

- 侧栏和检查器离场期间仍渲染，但不可交互。
- 弹窗关闭时焦点立即返回，离场节点 inert。
- backdrop 与 surface 同步卸载。
- 菜单按 top/bottom 使用正确方向。
- 设置 tab 只替换内容，不动画外框尺寸。
- 新聊天条目有动画标记，历史和会话切换条目无动画标记。
- 审批操作不因退出动画延迟。

### 11.3 样式契约

- 必需 motion token 与缓动曲线存在。
- reduced-motion 同时覆盖动画、transition、delay 与循环。
- 禁止 `transition: all`。
- 核心进入/退出只使用允许属性。
- 进度条使用 transform，不再 transition width。
- 静态区域没有新增批量动画。

### 11.4 人工检查矩阵

- macOS 与 Windows。
- 明亮与深色主题。
- 常规宽度、920px 附近和最小窗口宽度。
- 鼠标、键盘、Escape、快速重复开关。
- 系统 reduced-motion 开与关。
- 长聊天历史、流式任务、工具调用、审批、错误与终止。

### 批次 2：核心连续性

## 13. 验收标准

1. 侧栏、检查器和核心弹窗具有方向正确的进入与退出动画，关闭不再瞬间消失。
2. 关闭阶段的节点不可点击、不可聚焦，不延迟业务语义。
3. 菜单动画方向与实际出现方向一致。
4. 历史消息不重播动画，实时新增离散条目保持轻进入。
5. 流式正文、代码、diff、文件树、搜索重排和拖拽宽度保持静态。
6. reduced-motion 下无非必要移动或循环，Presence 不等待动画。
7. 无新增动画依赖，无 `transition: all`，无新增布局尺寸动画。
8. 相关单元测试、组件测试、样式契约、类型检查和现有回归测试通过。

## 14. 非目标

- 不建立营销式页面转场。
- 不增加粒子、渐变扫光、骨架 shimmer、视差或背景环境动画。
- 不重构业务状态、IPC、数据库或 Agent 执行流程。
- 不在本轮修复所有既有键盘与弹窗语义问题；只处理 Presence 直接涉及的焦点、inert 和状态时序。
- 不引入通用布局动画引擎。
