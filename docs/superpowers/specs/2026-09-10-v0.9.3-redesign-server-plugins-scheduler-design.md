## 1. 背景

0.9.3 是一次面向产品形态的版本升级，包含四块内容：

1. **全量界面重设计**：按参考图风格重写应用外壳、侧栏、首页、会话视图与设置皮肤，保持无账号登录。
2. **服务器连接**：接入 opencode 兼容服务端（默认 `http://localhost:4096`，Basic 鉴权），把服务端会话完整对齐到现有对话体验。
3. **插件市场**：建立面向能力扩展（MCP / Skill / Agent / 主题）的统一市场数据层与浏览 UI，本期不上架任何插件。
4. **已安排**：完整定时调度器（一次性 / 间隔 / Cron），托盘驻留 + 启动错过补偿。

现有底座已具备：主进程 IPC + SQLite 会话库、本地 Agent 循环（Responses / Anthropic）、设置面板、MCP / 技能 / 记忆 / AI 浏览器、系统通知。本版本在其上叠加，不替换本地 Agent。

## 4. 服务器连接子系统

### 4.1 数据与存储

- `config.json` 的 `app.servers[]`：

  ```ts
  interface ServerEntry {
    id: string;            // uuid
    name: string;          // 显示名，默认取 URL host
    url: string;           // http/https，无尾斜杠
    username?: string;     // 默认 'opencode'
    createdAt: string;
    lastConnectedAt?: string;
  }
  ```

- 密码单独存 `.env`（复用 `electron/config/secrets.ts` 的 safeStorage 加密链），键名 `STELLARA_SERVER_<id>`；**永不回传渲染层**，IPC 只暴露 `hasPassword: boolean`。
- 会话表新增列（db.ts 迁移）：

  ```sql
  ALTER TABLE sessions ADD COLUMN runtime TEXT NOT NULL DEFAULT 'local';
  ALTER TABLE sessions ADD COLUMN server_id TEXT;
  ALTER TABLE sessions ADD COLUMN remote_session_id TEXT;
  ```

- 服务器会话本地行只存元数据（id、title、runtime='server'、server_id、remote_session_id、时间）；消息正文不落本地库。

### 4.2 主进程 opencode 客户端（`electron/server/`）

- `opencode-client.ts`：轻量 HTTP + SSE 客户端。
  - 原生 `fetch`（Electron 43 / Node 20+）发请求；`eventsource-parser`（现有依赖）解析 `GET /event` SSE。
  - Basic 鉴权头在客户端内部注入，凭据不跨模块传播。
  - 接口：`health()`、`listSessions()`、`createSession(title?)`、`getSession(id)`、`deleteSession(id)`、`updateSession(id, title)`、`listMessages(id)`、`promptAsync(id, body)`、`abort(id)`、`respondPermission(id, permissionID, response)`、`listProviders()`、`listAgents()`、`getPath()`、`getVcs()`，以及 `subscribeEvents(onEvent)`（含指数退避重连，1s → 30s 封顶，`connected` 时重置）。
  - 超时：普通请求 15s；健康检查 5s。
- `server-manager.ts`：服务器 CRUD（读写 config + secrets）、连接生命周期、状态机（`disconnected` → `connecting` → `connected` / `error`）、当前激活服务器、向渲染层广播状态。
- `types.ts`：本版本所需的 opencode 类型子集（Session、Message、Part、Permission、Provider、Agent、事件联合类型），字段宽容解析（`unknown` 输入 + 运行时窄化），避免版本耦合。

### 4.3 事件适配层（`event-adapter.ts`）

把 opencode SSE 事件映射为现有 `ChatStreamEvent`，渲染层零感知执行端差异：

| opencode 事件 | 映射 |
|---|---|
| `message.part.updated`（text / reasoning） | 文本增量事件（替换与追加语义对齐现有 `delta`） |
| `message.part.updated`（tool） | `tool_call`（state 未完成）/ `tool_result`（completed、error） |
| `message.updated` | 消息元数据、token 用量（若可用） |
| `permission.updated` | `ApprovalRequest`，注册 approvalId → `{ serverId, sessionId, permissionID }` 映射表 |
| `session.idle` | 流结束事件 |
| `session.error` | 错误事件（含可重试提示） |
| `session.updated` | 会话标题 / 状态更新（侧栏实时刷新） |
| `session.deleted` | 移除会话映射行并刷新侧栏 |
| `message.removed` / `message.part.removed` | 忽略（本期不做重放） |
| 其他（`file.edited`、`storage.write`、`installation.updated` 等） | 忽略 |

- 事件按 `sessionID` 过滤；仅当该会话存在活动 chat 流时才向渲染层转发对话事件，否则仅更新会话元数据。
- `approval:respond` 的布尔值映射为 `response: 'once' | 'reject'`（`remember` 语义本期不暴露）。

### 4.4 会话映射与消息适配

- `sessions:create` 扩展入参：`runtime`、`serverId`（本地路径参数与校验保持不变）；服务器路径调用 `POST /session`，再把本地映射行写入 sessions 表，返回本地行。服务器会话不要求配置本地模型，本地行 `modelId` 记录所选服务器模型（`providerID/modelID`）以便回显；未选择时使用服务器默认模型并允许为空。
- `sessions:list` 合并两来源：
  - 本地会话：现有逻辑 + `runtime: 'local'`。
  - 服务器会话：已连接服务器以实时 `GET /session` 为准，upsert 本地映射行，并对账删除服务器已不存在的映射行；未连接服务器展示缓存行并带 `offline: true`。
- `sessions:get` 按 `runtime` 分派：服务器会话拉 `GET /session/:id/message`，由消息适配器把 Message + Part[] 映射为现有 `MessageRow[]`（文本、工具调用、计划、审批记录；未知 part 降级为文本摘要）。
- `sessions:delete` / `sessions:rename` 服务器会话转发到 `DELETE/PATCH /session/:id`，成功后同步本地映射行。
- `chat:start` 按会话 `runtime` 分派：服务器路径发起 `POST /session/:id/prompt_async`（携带 `model: { providerID, modelID }` 与 `agent`），注册 streamId → 会话映射，事件由 4.3 转发。
- `chat:abort` 服务器路径调用 `POST /session/:id/abort` 并结束流。
- 模型 / Agent 列表：服务器会话模型选择器来自 `GET /provider`（已连接提供商 + 默认模型），Agent 来自 `GET /agent`。

### 4.5 设置 → 服务器（参考图 2）

- 列表行：状态点 + 名称 + URL + `…` 菜单（编辑、测试连接、设为默认、删除）；右上「+ 添加服务器」。
- 添加 / 编辑对话框字段：
  - 服务器 URL（必填，默认 `http://localhost:4096`）
  - 服务器名称（可选，留空取 host）
  - 用户名（可选，默认 `opencode`）
  - 密码（可选，write-only，编辑时不回显）
- 保存前执行健康检查 + 鉴权验证；错误分类提示：网络不可达 / 401 鉴权失败 / 非法协议（仅 http/https）。取消 / 添加服务器按钮按图排版。
- 删除需二次确认；「设为默认」决定顶栏选择器默认高亮项与新建会话默认执行端（默认仍为本地）。

### 4.6 执行端切换

- 顶栏选择器控制**新会话**执行端；已有会话锁定创建时的执行端，会话内显示执行端徽标。
- 「新对话」在服务器模式下：进入首页，输入卡 chips 显示所选服务器；发送时创建服务器会话。
- 服务器模式下本地专属能力（计划模式本地审批链路、AI 浏览器工具面板）按服务器事件可用性自然降级：服务器未发事件则不展示，不做本地注入。

### 4.7 安全与容错

- URL 仅允许 `http` / `https`，其余协议（含 `file:`）拒绝。
- 凭据只存在主进程；渲染层仅见 `hasPassword`。
- 断线：状态点 + 可重试横幅；发送请求在未连接时立即失败并提示，不静默排队。
- SSE 断线重连后刷新会话列表与状态；重连期间的对话事件不补发，由 `sessions:get` 全量拉取兜底。

### 4.8 范围边界（本期不做）

- 分享 / fork / revert / summarize / init / shell 会话接口。
- TUI 控制接口（`/tui/*`）。
- 服务器端斜杠命令（`POST /session/:id/command` 本期不接，命令文本按普通消息发送）。
- 服务器提供商 OAuth 登录流（`/provider/*/oauth/*`）。
- 服务器文件接口（`/find`、`/file`）。

## 6. 已安排（调度器）

### 6.1 数据模型（SQLite 新表）

```sql
CREATE TABLE scheduled_tasks (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  prompt TEXT NOT NULL,
  project_id TEXT,
  work_dir TEXT,
  runtime TEXT NOT NULL DEFAULT 'local',
  server_id TEXT,
  model_id TEXT,
  schedule_kind TEXT NOT NULL,      -- 'once' | 'interval' | 'cron'
  schedule_expr TEXT NOT NULL,      -- ISO 时间 / 分钟数 / cron 表达式
  enabled INTEGER NOT NULL DEFAULT 1,
  next_run_at INTEGER,
  last_run_at INTEGER,
  last_status TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE scheduled_runs (
  id TEXT PRIMARY KEY,
  task_id TEXT NOT NULL,
  started_at INTEGER NOT NULL,
  finished_at INTEGER,
  status TEXT NOT NULL,             -- 'running' | 'success' | 'error' | 'missed' | 'aborted'
  session_id TEXT,
  error TEXT,
  FOREIGN KEY (task_id) REFERENCES scheduled_tasks(id) ON DELETE CASCADE
);
```

### 6.2 调度引擎（`electron/scheduler/`）

- 新增依赖 `croner`（纯 TS、零依赖；支持 cron / 间隔 / 一次性）。
- `scheduler.ts`：
  - 启动时加载启用任务 → 计算 `next_run_at` → 为最近任务设置计时器（单计时器 + 最小堆，避免每任务一个 timer）。
  - 到点执行：创建会话（本地或服务器）→ 运行：
    - 本地：复用 Agent 循环，抽出事件 sink 抽象（现有 IPC 场景 sink = `webContents.send`；调度场景 sink = no-op + 结果落库）。模型未配置或工作目录非法时任务标记 `error` 并写明原因。
    - 服务器：`POST /session` + `prompt_async`，订阅事件等待 `session.idle`（超时 30 分钟视为失败）。
  - 执行记录写入 `scheduled_runs`；完成 / 失败发系统通知（复用 `electron/notifications.ts`）。
  - `once` 任务执行后自动 `enabled = 0`；`interval` / `cron` 重算 `next_run_at`。
  - 支持手动「立即运行」，与定时执行走同一路径。
  - 运行中可取消（本地走 agent abort；服务器走 `/abort`），状态记 `aborted`。

### 6.3 托盘驻留

- 主进程新增托盘（macOS 菜单栏 / Windows 托盘）：
  - 图标：新增 `assets/trayTemplate.png` + `trayTemplate@2x.png`（macOS 单色模板图），Windows 用 `assets/tray.png`（32×32）。
  - 菜单：打开主窗口、暂停 / 恢复调度、退出。
- 关闭主窗口 → 隐藏到托盘（不退出）；Cmd+Q / 托盘「退出」完全退出。
- 新增设置 `app.backgroundScheduling`（默认 `true`，位于设置 → 应用）：关闭时关闭窗口即退出，行为与现版本一致。

### 6.4 错过补偿

- 应用启动时扫描 `enabled = 1 且 next_run_at < now` 的任务：
  1. 先为错过的周期补写一条 `status = 'missed'` 的执行记录（标注原定时间）；
  2. 随后立即补跑一次，补跑的运行记录按实际结果记 `success` / `error`；
  3. 重算 `next_run_at`。
- 同一任务多个错过周期只补写一条 `missed` 记录并补跑一次，不连续追补。

### 6.5 UI（已安排页）

## 7. IPC 与共享类型

- `shared/ipc.ts` 新增类型：`ServerEntry`（含 `hasPassword` 视图）、`ServerStatus`、`ServerTestResult`、`PluginEntry`、`PluginCategory`、`ScheduledTask`、`ScheduledRun`；`Session` / `SessionSummary` 增加 `runtime`、`serverId?`、`remoteSessionId?`、`offline?`。
- IPC 变更（均走现有 trusted `handle` / `on` 包装）：

| channel | 入参 → 返回 |
|---|---|
| `servers:list` | — → `ServerEntry[]` + 状态 |
| `servers:add` / `servers:update` | 配置（密码可选）→ 校验后的条目 |
| `servers:remove` | id |
| `servers:test` | id → `ServerTestResult` |
| `servers:setDefault` | id |
| `servers:status` | — → 各服务器状态；状态变化经 `servers:status-changed` 推送 |
| `plugins:catalog` / `plugins:get` | 查询 → 条目 |
| `plugins:refresh` | — → 目录 |
| `scheduled:list` / `scheduled:create` / `scheduled:update` / `scheduled:remove` | CRUD |
| `scheduled:toggle` / `scheduled:runNow` | id |
| `scheduled:runs` | taskId → 最近记录 |
| 事件推送 | `scheduled:changed`、`servers:status-changed` |

- `sessions:list` / `sessions:create` / `sessions:get` 等按第 4 节分派，签名向后兼容。
- preload 新增 `servers`、`plugins`、`scheduled` 命名空间；`src/dev-preview.ts` stub 同步补齐。

## 8. 数据迁移

- sessions 表三列迁移采用现有 `PRAGMA table_info` 检测模式，幂等执行。
- 新表 `CREATE TABLE IF NOT EXISTS`。
- `config.json` 的 `app.servers`、`app.pluginCatalogUrl`、`app.backgroundScheduling` 均为可选字段，旧配置读取时补默认值，`schemaVersion` 维持 1。
- 现有本地会话 `runtime` 默认 `local`，行为不变。
