# Stellara Work 0.9.3 服务器连接 — 渲染层接入实施计划（Plan 2B/2B）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让用户在 UI 中完成服务器连接全流程：设置面板管理服务器（图 2）、顶栏切换执行端、在服务器上新建/对话、会话模型/Agent 切换、离线提示与重连。

**Architecture:** 复用 Plan 2A 的 `servers:*` / `sessions:*` / `chat:*` 主进程桥接；渲染层新增设置面板、执行端选择器、服务器会话控件与侧栏分组；MainView 持有执行端与服务器模型选择状态，`chat.start` 透传 `serverModel/serverAgent`（主进程已持久化）。

**Tech Stack:** React 19 + TypeScript + Vitest（jsdom，手动 createRoot harness）；Electron IPC via `window.electronAPI`。

**Spec:** `docs/superpowers/specs/2026-09-10-v0.9.3-redesign-server-scheduler-design.md`（3.2–3.4、4.4–4.7）

## Global Constraints

- 无新 npm 依赖；类型严格（`noUnusedLocals`）；全量 `npm test` 每任务保持绿色。
- 凭据永不进入渲染层：UI 只见 `hasPassword`；密码输入框 write-only。
- 本地模式行为不回归：默认执行端仍是本地，本地会话/发送/模型切换路径不变。
- 服务器会话使用服务器工作目录：不在服务器模式要求本地项目/工作目录。
- 中文文案；沿用现有组件类名与 harness 模式（手动 `createRoot` + `act`；`installApi` 覆写 `window.electronAPI`）。
- Plan 2A 已提供：`servers.list/add/update/remove/test/setDefault/status/connect/providers/agents/onStatusChanged`；`sessions.create` 接受 `runtime/serverId/serverModel`；`chat.start` 接受 `serverModel/serverAgent`；`AppSettings` 暂无 `defaultServerId`（本计划暴露）。
